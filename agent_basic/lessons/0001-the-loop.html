第 1 課 · 一個 agent 的心臟：迴圈

agent_basic 讀書會 · 約 12 分鐘 · 對照檔案：01_loop.py（60 行）→ agent.py 的 execute_task

這一課的收穫：讀完後打開 agent.py 的 execute_task，你能用手指出「問模型 → 有沒有 tool_calls → 執行工具 → 塞回歷史」四個區塊，其他 900 行都只是這四塊的裝飾。

先把定義縮到一句話

Anthropic 對 agent 的定義是「LLMs using tools based on environmental feedback in a loop」[1]。拆開來就是三個名詞：模型、工具、迴圈。模型不會自己執行任何東西，它只會「說」要用哪個工具；真正動手的是你的 Python 程式，然後把結果餵回去，再問一次。

最小版本：01_loop.py 的四個區塊

先在 VSCode 打開 agent_basic/01_loop.py。建議從最底下的迴圈往上讀。

區塊 4 · 迴圈（先看這裡；節錄，print 行省略）

for step in range(10):                          # 上限：避免模型卡住一直叫工具
    resp = client.chat.completions.create(model=MODEL, messages=messages, tools=TOOLS)
    msg = resp.choices[0].message
    messages.append(msg)                        # 模型說的話也是歷史的一部分（含它的 tool_calls）

    if not msg.tool_calls:                      # 沒有要用工具 = 它認為答完了
        print(msg.content)
        break

    for call in msg.tool_calls:                 # 一輪可能同時要求多個工具
        args = json.loads(call.function.arguments)
        result = run_tool(call.function.name, args)
        messages.append({"role": "tool", "tool_call_id": call.id, "content": result[:4000]})

三行被標起來的就是整個 agent 的規則：

  1. 模型的回覆要先 append，因為它裡面帶著 tool_calls（它「說」要用什麼工具）。
  2. 沒有 tool_calls 就是結束。模型用「不叫工具、直接講話」來表示它答完了。
  3. 工具結果用 role: "tool" 送回，並附 tool_call_id 對上是回答哪一次呼叫。

這三條不是這份程式自己發明的，是 OpenAI 相容 API 的規格。OpenRouter 文件用一模一樣的流程描述，範例也是上限 10 輪 [2]。

區塊 1 · 工具契約（TOOLS）

一份 JSON Schema，告訴模型「有個叫 run_shell 的函式，吃一個字串 command」。模型只看得到這份描述，看不到你的 Python。

區塊 2 · 工具實作（run_tool）

模型說「我要 run_shell」時真正跑 subprocess 的地方。名字要跟區塊 1 對得上。這兩塊為什麼分開、怎麼對上，是第 2 課。

區塊 3 · 對話歷史（messages）

一個普通的 Python list。每一輪整份送給模型。agent 的「記憶」就只是這個 list，第 3 課。

所以 execute_task 約 200 行，骨架跟 60 行的最小版一樣。多出來的每一段都屬於後面某一課。

這些可以先跳過

  • _advance_simulated_time、simulate_time_delay：書裡 demo「多天任務」用的假時鐘。
  • _reasoning_safe_temperature：某些 reasoning 模型只接受 temperature=1 的小補丁。
  • "FINAL ANSWER:" in content 那幾行：舊版用字串當結束訊號，現在「沒有 tool_calls」才是真正的結束條件。
  • _save_trajectory(iteration)：每輪把狀態 dump 成 JSON，第 6 課再看。

預測一下

選一個答案，立刻看解釋。目的是檢查你有沒有把上面三條規則讀進去，不是考試。

模型回傳的訊息裡沒有 tool_calls，迴圈接下來會怎樣？

「不叫工具」就是模型表示答完了。這是 01_loop.py 的 if not msg.tool_calls: break，也是 agent.py 的 if not has_tool_calls: 分支。

如果忘了 append 模型那條帶 tool_calls 的訊息，只 append 了 role: "tool" 的結果，下一輪會怎樣？

API 要求每條 role: "tool" 必須接在一條帶 tool_calls 的 assistant 訊息後面，tool_call_id 要對得上。少了前一條，伺服器會拒絕整個請求。這就是為什麼 messages.append(msg) 要在執行工具之前。

for step in range(10)（agent.py 的 max_iterations=20）主要防的是什麼？

模型可能一直叫工具永遠不給答案（例如每次都 ls）。上限是最便宜的保險；工具跑太久由 subprocess.run(timeout=30) 另外防。
